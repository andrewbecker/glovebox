# Debugging through lldb-dap

**Setup.** Xcode 27.2's `lldb-dap`
(`/Applications/Xcode.app/Contents/Developer/usr/bin/lldb-dap`), TestApp
built with `-Onone -g`, iPhone 18 Pro on iOS 27.2.

**Run.** `simctl launch --wait-for-debugger`, then DAP `initialize`, `attach
{pid}`, the `initialized` event, `setBreakpoints` for TestApp.swift line 35
(Submit's action), `configurationDone`; then glovebox taps Form, types a name and
taps Submit.

**Result.**

- `attach` by pid works on a simulator app with no extra options; module
  events stream for about a second.
- `configurationDone` resumes the app that `--wait-for-debugger` held.
- A function breakpoint on `TestApp.FormScreen.body.getter` stayed
  unverified; the file:line breakpoint verified at once (column 29).
- The tap on Submit stopped the app (`stopped`, reason breakpoint). glovebox's
  tap then saw no screen updates, as expected for a frozen app.
- `evaluate` in `repl` context took both expressions (`count` gave
  `(Int) $R0 = 0`) and lldb commands (`p name` gave `(String) ""`).
- `continue`, then `disconnect {terminateDebuggee: false}`, left the app
  running.

**Decision.** glovebox's debugger tools wrap exactly this sequence. While the
app is paused, input tools and `describe_ui` are refused, and screenshots are
labelled frozen. System apps (outside the device's `data/Containers/Bundle`)
and processes already traced are refused.
